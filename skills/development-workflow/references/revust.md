# Optional revust adapter

Read this only when the applicable review route selects revust. Resolve its
installed skill through the real registration and follow its package, launcher,
host and archive instructions. Do not install/upgrade the engine or change
provider profiles as an incidental preparation step. A missing required package
is a gap for that review, not a reason to block unrelated local implementation.

Inspect effective configuration in the actual caller directory without exposing
credentials. Preserve explicit profile/provider/model choices. Freeze the scope
and reviewed snapshot in the task worktree or authorized archive. Keep the main
checkout free of generated review/task files by selecting supported caller,
workdir and tasks paths. Preflight is not a paid capability test.

## One architectural pass

Use the selected package's documented single-reviewer composition (for example
`--lenses` with only the architectural lens), `--no-synthesis` and `--no-verify`.
Inspect actual lens names and resolved prompts rather than guessing them.
Disable finder retries and bound max_calls to 1 through supported invocation or
scoped policy. Do not overwrite authored global/project profiles to achieve it.
Check that inherited completeness gates do not require the deliberately omitted
stages. A lone general reviewer or an architecture+quality roster is not enough:
the assignment must inspect design feasibility, boundaries and complexity.

Inspect effective configuration and dry-run without provider calls: exactly one
reviewer, synthesis/verify disabled, retries zero and at most one provider start.
If the installed version cannot express this intent, report that limitation;
do not silently run a multi-stage profile or modify revust source from agflow.
A dedicated convenience mode is a separate possible revust change, not a
prerequisite when existing composition can express the intent.

## Execution and recovery

Check original round allowance before launch. Use the installed launcher with
actual host identity; in Guild preserve owning session/socket and use supported
terminal jobs. Existing registered native runs use their owning controller;
never launch the external route alongside it. Respect selected auto-close
presentation (default `--auto-exit=1s`) without cancelling a live job.

Reconcile lost acknowledgements with the same job/request/archive. Retain exact
snapshot, findings, actual calls and incomplete outcomes; exit code 1 means
findings, not retry. Closing a view is not cancellation. Provider failure does
not authorize a different model or another attempt. Apply the workflow's cause,
changed-condition, free recovery evidence and explicit scoped exception policy
within remaining allowance. Preserve archives and do not reset task IDs/budgets.
